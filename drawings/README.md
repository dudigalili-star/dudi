# שרטוטים לספק

עמוד `drawings.html` (קישור "📐 שרטוטים לספק" בתפריט של חשבונית+).

**תהליך העבודה:** צילום או סקיצה ← ניתוח AI (Claude) ← בדיקה ותיקון מידות בטופס ← שרטוט A4 (PDF), ולחלקים מורכבים גם STEP ו-DXF ← מייל לספק בפורמט הקבוע ← ZIP עם כל הקבצים.

- כל חלק נשמר כמפרט JSON אחד (`model.js`). השרטוט, המודל התלת-ממדי, ה-DXF והמייל נוצרים כולם ממנו, כך שאין סתירות בין המייל לשרטוט.
- סוגי חלקים: סיבובי (מקטעים, פאזות, הברגות, קדחים בציר, חורים רוחביים), פלטה/שייבה (מלבן, אובל, עיגול, חורים והברגות), קפיץ לחיצה, ואחר (תמונה + הערות).
- "סט מלא" (PDF+STEP+DXF) נבחר אוטומטית לחלק מורכב: יותר משני מקטעים, הברגות, קדחים או יותר מארבעה חורים. אפשר לשנות ידנית.
- הנתונים, ההגדרות ומפתח ה-API נשמרים רק בדפדפן (localStorage).

**קבצים**

| קובץ | תפקיד |
|---|---|
| `model.js` | מבנה החלק ובדיקות תקינות |
| `drawing.js` | מבטים, מידות, הערות וטבלת כותרת |
| `render.js` | פלט SVG, PDF ו-DXF |
| `cad.js` | יצירת STEP |
| `ai.js` | קריאה ל-Claude |
| `email.js` | טקסט המייל |
| `app.js` | ממשק המשתמש |

**ספריות:** `vendor/` מכיל את jsPDF, JSZip, Anthropic SDK ו-replicad/OpenCascade, ארוזים מראש כדי שהעמוד יעבוד בלי CDN. מנוע ה-WASM שוקל כ-23MB ונטען רק כשמבקשים קובץ STEP.

**הרצה:** צריך להגיש את הקבצים משרת, למשל GitHub Pages או `python3 -m http.server`. פתיחה ישירה של הקובץ (`file://`) לא תעבוד, כי מודולים של JavaScript לא נטענים כך.
